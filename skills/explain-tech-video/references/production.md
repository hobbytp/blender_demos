# 制作与验收要点

## 分层与工具

复用已安装的渲染器、组件和播放器。画面层通常可拆为背景、拓扑/分组、节点外观、内部组件、消息/通知、状态结果、字幕。拆分是为了独立运动与保持准确性，不要求搭建通用场景引擎。

生成式插画适合作为服务器等外观素材；保留来源、提示词和使用范围。声称透明的图片可能把棋盘格画进像素，需检查真实 alpha；发现问题用图像工具修正或生成纯色背景再按合适方式合成。白底素材使用 multiply 可融入浅底，但不适用于任意深色背景。中文标签与票数等事实文本优先由代码渲染。

## 帧与状态

- 每帧从帧号推导结果。网络消息、颜色、成员、票数、请求结果等不能依赖播放累计的可变状态，否则回拖与导出会不一致。
- 将协议状态与讲解揭示进度分开。检测期间若尚不能推断结果，显示未知/等待；不要提前保证成功。
- 短片扩展时复用组件，用分段时间映射重排关键动作；流动消息使用自己的实际帧时钟，避免所有东西一同变慢。
- 让共享状态函数用于渲染与测试。最小检查覆盖触发前、检测中、状态稳定、通知与请求结果、倒退重播；按场景验证不变量，别只检查画面有某段字。
- 字体与图片在渲染前加载完成。Remotion 可用 delayRender/continueRender 等既有加载机制，失败应可观察；查询项目已安装版本，不照搬未经核实的 API。

## 旁白与字幕

1. 为每个片段分配 start/end 和短句 chunks；生成真实语音后测量时长。
2. 保证语音时长落在时间槽内，并保留少量余量。超长先缩短表达或重新分配时间；不能通过截断末尾掩盖问题。
3. 用提供者的词边界，或对已提供音频做强制对齐，生成字幕与动作时间点。不要把一句话按字符数均分当作精确对齐。
4. 已测试的 Edge TTS 路径使用显式 `boundary="WordBoundary"`；省略时可能得到句边界。服务接口与版本会变，优先确认当前脚本与实际返回内容。
5. 规范化文本匹配时校验词边界覆盖完整文本，尤其注意英文缩写、数字与标点；不匹配就修正，不悄悄丢字幕。
6. 同步检查按“旁白提到事件 → 画面发生 → 结果可读”的顺序进行；不要只看音频总长。

Windows 实践：PowerShell 执行策略可能阻止 npm.ps1，改用 npm.cmd/npx.cmd。Python 不可用时，可沿用已安装 uv 的 `uv run --with <依赖> python <脚本>`；缓存路径和联网权限以实际环境为准，不把本机绝对路径写进新项目。

## 检查真正的输出

检查源代码、浏览器和 MP4 是三件事。至少执行一次实际渲染；如果当前仅获准制作风格帧，不冒充已完成视频。

- 用 ffprobe 核对视频尺寸、fps、帧数、视频时长以及音轨存在。AAC 容器/音轨可能比视频轨稍长，区分它们。
- 完整解码音视频，抽取关键状态、转场中间、通知传递和片尾帧进行视觉检查。源码截图不能替代成片检查。
- FFmpeg 精简构建可能缺少某些滤镜、muxer 或默认编码器。先看本机构建能力；例如某些 Remotion Windows 构建解码检查需要显式指定 `-c:v rawvideo -c:a pcm_s16le -f null -`。
- 空白/冻结等指标只作排查线索。不要通过增加装饰粒子“通过动效比例验收”。
- 对交互版检查所有章节起点、拖动到动作中间及倒退、暂停/恢复、静音与取消静音、末帧停止及再次播放。浏览器更新是异步的，等待可观察状态而非点击后立即读取。
- 已发现的播放器坑：结束事件只设置“暂停”可能留下上一次 frameupdate 的旧进度；结束时显式同步末帧，再验证再次播放确实从头开始。
- 浏览器截图若坐标/缩放异常，先区分抓取工具问题与产品问题，并用实际渲染帧交叉验证。

交付说明区分“状态/工程检查通过”“视觉已检查”“用户认可样片”“新观众已理解”。这些结论不能互相替代。
