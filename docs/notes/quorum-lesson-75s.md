# 75 秒内部动态试讲

用户确认 30 秒内部动态版可用后要求继续。本轮沿用原访谈已确认的 75 秒、七段结构，扩为“网络分区与 quorum”完整试讲；并非已经完成所有 Corosync 课程章节。

## 观看和复现

- 预览：`http://127.0.0.1:5173/?sample=lesson`
- MP4：`out/quorum-lesson-75s.mp4`
- 渲染：`npm.cmd run render:lesson`
- 旁白：`uv run --with edge-tts==7.2.8 python scripts/dark-narration.py lesson`
- 旧样片：`?sample=flow`（已确认的 30 秒版）；`/`（最初 75 秒版）。

## 教学安排

| 时间 | 展示内容 |
| --- | --- |
| 0–7 秒 | 三台服务器保持开机，提出“为什么有一台不能修改配置”的问题。 |
| 7–20 秒 | 原位展开 Corosync 内部通信、成员管理、votequorum，以及进程外 pmxcfs；角色提示依讲解高亮。 |
| 20–30 秒 | 到 C 的全部有效通信路径中断，消息在断点消失，经历检测与成员重组。 |
| 30–43 秒 | A+B / C 的成员视图分离，成员信息下传；强调预期总票数仍为 3。 |
| 43–55 秒 | 比较可见票数与门槛；三票位和两票分界辅助理解，仲裁状态下传 pmxcfs。 |
| 55–67 秒 | 修改同一 VM 100 描述，WRITE 请求进入 A、C 文件系统并返回保存 / 拒绝。 |
| 67–75 秒 | 逐项点亮因果链，说明配置只读不等于虚拟机立即停止，引出 HA/watchdog。 |

复用 `QuorumFlow` 渲染组件，75 秒入口为 `QuorumLesson`。`lesson-timeline.ts` 映射教学动作节点，网络消息使用实际帧时钟保持流速；不是把原 30 秒音视频整体慢放。旁白重新编写，字幕由词边界对齐。两种时长共享视觉组件，旧版仍独立可播放。

所有时间均为教学编排。检测条不是实测协议进度；状态通知的先后展示不能用于推断真实回调延迟。适用固定三节点、每节点一票、无 QDevice、无特殊设置的场景。网络路径与内部事件均为概念示意，没有模拟 Totem/KNET 包格式；配置写入只比较同一对象的 pmxcfs 文件层行为，不扩展为 GUI/API、权限、锁或复制事务的实现演示。

## 依据与评价

- [Corosync votequorum](https://github.com/corosync/corosync/blob/main/man/votequorum.5)：多数票仲裁。
- [Proxmox pmxcfs](https://github.com/proxmox/pve-docs/blob/master/pmxcfs.adoc)：配置文件系统、文件布局与失去 quorum 后只读。
- [Proxmox HA](https://github.com/proxmox/pve-docs/blob/master/ha-manager.adoc)：运行、隔离与恢复的后续机制。

自动验证遍历全部 2250 帧并倒序检查：章节与原始约定一致、三节点成员状态一致、检测区间保持 20–30 秒、固定门槛不变、仲裁/通知/请求顺序成立；全部 12 段旁白均在对应时间槽内。7 项测试和 TypeScript/Vite 构建通过。

实际成片验证：H.264 + AAC、1920×1080、30fps、2250 帧，视频轨 75 秒，音轨约 75.05 秒；完整解码无错误，抽查实际编码后的多数门槛和片尾回顾帧。浏览器七个章节分别跳至 0/7/20/30/43/55/67 秒并暂停，静音状态可切换，重播归零。修正结束事件只切换播放按钮而未同步进度的问题；实际验证结束落在 2249 帧，随后点击播放从头继续。

教学评价建议：让第一次观看的人复述“通信中断 → 成员变化 → 仲裁判断 → 配置写入限制”，再解释为何电源亮着仍可能无法修改配置。若复述有断点，应调整对应段落，不以动效数量替代理解效果。后续配置复制、冗余链路、HA 分开讲解。
