## F3 的 30 秒候选分镜

选定正常运行的 Linux VM、可冻结的本地文件系统、已启用并运行的 QGA、冻结选项开启，单虚拟磁盘、正常命令返回。本片只演示备份启动阶段，结束时备份仍在复制；不宣布备份成功或可恢复。样片不加入应用专用 hook、Windows VSS、PBS 去重、fleecing 或错误恢复。

| 时间预算 | 旁白草稿 | 固定架构上的动作 / 可见状态 |
| --- | --- | --- |
| 0–8 秒 | 备份任务先请求冻结。来宾代理同步并冻结文件系统。 | Host 备份编排 → QGA → Guest 文件系统；等待响应后显示 frozen，不把整台 VM 涂成停止 |
| 8–15 秒 | 冻结成功后，建立备份任务。启动返回，不代表复制完成。 | Host 向 QEMU 发送 backup；QEMU 返回任务标识；备份状态仅显示已启动 |
| 15–23 秒 | 随后解冻文件系统。备份数据仍继续复制。 | thaw 控制走回 Guest；成功返回后解除冻结；蓝色备份数据流继续独立移动 |
| 23–30 秒 | 文件系统冻结，不替代应用自己的协调与恢复验证。 | 同屏显示 FS 已解冻 / backup 进行中 / 应用协调未验证；停在三个不同证据层 |

旁白尚未生成 TTS；上述时间仅用于分镜预算，不是测得的语音时长或协议超时。正式制作时按实际词边界对齐，并补齐选定 QEMU 备份路径内部保护旧数据的实现证据；不能把 snapshot 模式擅自画成存储后端快照。

## 本轮已核实的事实

本地 qemu-server commit `6c0127e612f6c576888a13f9bfb30874911b804d`；pve-docs commit `1e5d5ec701776acc2d8ab3dca996a27c7a60aee8`。二者是源码快照，不宣称某台 PVE 已部署相同二进制组合。图工具本轮返回 Transport closed，改用定点源码读取。

- `src/PVE/VZDump/QemuServer.pm:810–862` 的 PBS 路径：尝试 freeze → QMP backup → 条件 thaw → 检查启动结果 → 查询备份进度。thaw 不等待完整复制结束。
- 同文件约 `1026–1053` 的归档路径也在启动命令执行后尝试 thaw，随后才进入备份状态查询。两种后端不混画成一条未经核实的内部数据流。
- 同文件 `1094–1116`：`qga_fs_freeze` 捕获冻结错误并记录，仍返回 1，以确保稍后尝试 thaw。因此局部变量 `fs_frozen` 不是冻结成功的可靠证据；动画状态应来自明确成功的响应和选定案例条件。
- `src/PVE/QemuServer/Agent.pm:309–332` 检查冻结配置、QGA 运行状态和是否已经冻结。配置启用不代表 QGA 实际可用。
- 当前源码的选项名称为 `freeze-fs`；`freeze-fs-on-backup` 是旧别名。不要不加版本限定地照搬旧教程选项名。
- 本地 `vzdump.adoc:79–86` 将 VM snapshot 模式描述为运行时复制数据块，并通过 QGA freeze/thaw 改善一致性；不能由名称推出必须依赖存储后端快照。
- [QEMU Guest Agent 协议](https://www.qemu.org/docs/master/interop/qemu-ga-ref.html#command-guest-fsfreeze-freeze)说明 freeze 同步并冻结可冻结的来宾本地文件系统，返回冻结数量；它没有承诺替应用完成跨服务事务或恢复验证。此网页为查询时的 master 文档，正式成片还需固定 Guest QGA 实现版本。

## 制作前需要固定的边界

1. 确定第六集主题；选 Ceph 时明确采用教学集群而非假定用户已部署。
2. 若选 F3，固定归档或 PBS 备份路径，再追踪 QEMU 在 thaw 后保护备份时间点数据的实现；30 秒片不把未展开部分画成即时复制完成。
3. 样片先走无错误路径；错误章节另作独立对照，冻结错误不能静默呈现为应用一致性已成立。
4. 保留应用 / QGA / 文件系统 / QEMU / 备份目标五类职责，控制命令和备份数据分色，FS 状态与备份进度独立显示。
