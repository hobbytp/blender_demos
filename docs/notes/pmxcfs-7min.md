## 章节与可观察过程

| 时间 | 主题 | 可观察的动作与区别 |
| --- | --- | --- |
| 00:00–00:30 | 同一个配置对象 | A、B、C 入口比较同一规范路径，区别本地别名与虚拟磁盘 |
| 00:30–01:05 | 节点内部 | 依旁白聚焦 FUSE、进程边界、内存树、本地数据库与外部 Corosync |
| 01:05–01:45 | 写入资格 | 写请求进入→quorum 检查→发送操作→调用者等待；内存不提前改变 |
| 01:45–02:25 | 一致顺序 | 含发送节点的交付；独立 Q1/Q2 队列保持相同次序、错开交付时刻 |
| 02:25–03:05 | 本地更新 | 交付→memdb→SQLite；处理临界区内的新读取等待 |
| 03:05–03:45 | 返回条件 | A 取得本机处理结果并返回，C 稍后完成；区别磁盘确认与持久性 |
| 03:45–04:20 | 本地读取 | 读请求进入 A、本机配置树响应、结果返回；网络没有逐次读取查询 |
| 04:20–05:00 | 稳定分区 | A+B / C 已稳定；C 新写入在检查处被拒，旧 v2 本地可读 |
| 05:00–05:40 | 业务协作锁 | 独立健康场景；A 取得锁、刷新、执行、释放，B 随后取得并刷新 |
| 05:40–06:20 | 诊断边界 | 文件入口、quorum、消息交付、本机结果和业务锁逐项揭示 |
| 06:20–07:00 | 判断与回放 | 两题后揭示答案，再重新开始一项健康写入，回放完整因果链 |

11 段实际旁白合计 **380.808 秒**；其余约 39.2 秒为章节衔接和观察停顿。短片与长片音频分别保存，没有将原 30 秒视频整体慢放。

Q1/Q2 是独立交付顺序示例，不能看成主线 W1 又被修改了一次。锁章节也明确回到健康集群：演示 `cfs_lock_file` 支持的集群配置对象，不声称 VM 100 的配置操作使用该封装。片尾的健康路径为重新回放，不代表分区已经自动恢复。

## 专业审查意见与实际修订

- 分布式协议：AGREED 保证交付顺序，不暗示全节点落盘 ACK；用 A 返回时 C 仍处理中直接展示区别。
- 操作系统：pmxcfs 与 Corosync 分清进程边界；内存和后端更新之间的新读取显示等待，而非可读半成品。
- 存储：本地事务提交与断电持久性分开；本次没有增加虚拟磁盘、复制日志性能或断电实验的结论。
- 并发控制：业务协作锁与 memdb 内部互斥锁分别说明；两个调用者竞争同一目录，释放前 B 不进入业务临界区。没有把一般文件顺序当作自动业务事务。
- 教学：独立队列、锁示例和健康回放均在画面标明；不把跨章节跳回健康场景解释成实际故障恢复。
- 动效：复用已批准的三节点内部图，消息在各阶段短时移动，讲解停顿保留明确状态；静态卡片用于问题提示，核心机制由操作抵达和状态变化表现。

这些是制作中的专业视角核查，不是外部专家评审。沿用固定源码快照，本次额外复核 `PVE/Cluster.pm` 的 `mkdir → cfs_update → callback → rmdir` 路径；没有对真实 PVE 集群执行写入、抓包或断电实验。
