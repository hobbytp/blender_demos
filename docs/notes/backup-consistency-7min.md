## 观看与复现

- 成片：`out/backup-consistency-7min-v1.mp4`，与 30 秒样片分别保留。
- `npm.cmd run dev` → `http://127.0.0.1:5173/?sample=backup-lesson`。页面入口可切换到 `?sample=backup` 对照样片。
- `npm.cmd run render:backup-lesson`：H.264、1920×1080、30 fps、12600 帧。
- 默认脚本保留单并发、120 秒单次等待超时；本次进程 TEMP/TMP 指向 `out/backup-lesson-render-temp`。不修改系统环境，也不安装新依赖。
- 导出过程：首次单并发抽帧发现强调框压到 QMP 标签后主动停止，修正边框内收和底部间距。第二次双并发在 6283 帧后不再推进，未产生完整 MP4；停止进程，保留并检查 0–6282 帧连续 JPEG。使用已安装 Remotion 的 `--sequence --frames=6283-12599 --image-format=jpeg --concurrency=1` 生成余帧，再以 FFmpeg 合成。中间有一次误用 `--image-sequence`（本版本未识别）的尝试，已停止，其临时帧未纳入成片。
- 恢复合成：严格检查 12600 个连续帧；八段原 MP3 按 `backup-lesson-audio.json` 的起点转换为整数采样点，使用 `adelay=<samples>S:all=1` 混合，48 kHz、双声道，总长 420 秒；H.264 使用 CRF 18、veryfast、yuv420p，AAC 192 kbps。实际命令保存在本地 `out/backup-lesson-compose.ps1`；正常资源条件下仍可使用上面的 Remotion 一步导出命令。
- 八段已生成配音无需重建。只有实际改旁白才运行 `npm.cmd run voice:backup-lesson`，该脚本当前仍按整集生成，局部修改应先保留未受影响片段与元数据。

## 教学与状态边界

正常主线展示 QGA 冻结、保护建立、解冻、后台复制，以及未备份 X 与已备份 Y 的两类覆盖写。应用对照使用完整 PostgreSQL 集群同盘且干净停库到备份结束的保守方案，明确可用性代价。错误对照只跟踪冻结报错后的清理责任，实际最终 FS 状态未知。

不能把位图中“无需再次复制”直接等同于当前没有在途请求；动画的 Y 在新写之前已成功复制。两个示意块均完成也不代表整个归档完成。应用对照中的成功分支是选定假设，正常主线与片尾仍有其他块未复制。

产物可读、隔离恢复和业务校验以待核验清单呈现，没有真实 VM 备份、PostgreSQL 停启或恢复演练。
