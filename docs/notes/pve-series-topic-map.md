# PVE 系列主题地图与架构师优先级

状态：讨论草案，2026-09-13。用户已明确：面向资深系统架构师，快速掌握核心原理，倾向先制作难度高的主题。评分、主题范围与制作顺序是本轮建议，尚未成为最终课程规格。沿用已确认的内部组件、状态变化、数据流动画方式。

## 评分口径

- D：原理理解难度，1–10。按本表列出的解释深度，考虑跨层依赖、并发/一致性、异常状态与先修知识；不是安装操作难度，也不是动画制作工时。
- P：对资深系统架构师快速掌握 PVE 核心原理的学习优先级，1–10，越高越优先。综合架构覆盖、故障判断和设计决策价值；不是官方评分。假定已有操作系统、网络与分布式系统基础，尚未系统掌握 PVE 实现。
- D 1–3：基础操作；4–6：组件职责与配置；7–8：机制与跨层路径；9–10：一致性、状态转移、失效与恢复的深入推演。
- P 9–10：核心主线；7–8：重要专题；5–6：按使用场景补充；1–4：基础操作或当前低收益内容。
- 一个主题可拆成多集，本表的 32 个主题不是一次性承诺制作 32 集；主题难度与单集时长分别决定。

## 快速掌握路线

1. A1 → A2：先用一页责任图建立位置参照，再跟踪一次管理请求；不必先制作长视频。
2. B1 → B2 → B3：通信、成员、仲裁、配置状态，建立管理面一致性主线。已有视频覆盖 B1/B2 的入门场景，不代表已完成其深入专题或 QDevice。
3. D1 → D2，并补 E1 的网络边界图：弄清存储能力、写入持久性及故障域，建立数据安全判断依据。
4. C1 → C3：理解执行和 I/O 边界，为迁移与性能提供机制基础。
5. F1 → B4：分别掌握计划内迁移与故障后恢复；比较状态转移和接管前提。
6. D4 → D5 → B5：加入分布式存储，再综合推演多种网络/存储故障。
7. 按目标环境补 E2、F2/F3/F4、G1/G2/G3/G4；批量交付需求补 A5。Ceph、SDN、PBS 是部署相关分支；未采用这些组件时，可降低其近期学习优先级。

上述顺序承认先修依赖，不等于按难度从低到高铺完课程。B5 的学习价值为 10，但适合作为综合收束，不能仅凭分数提前到所有机制之前。
